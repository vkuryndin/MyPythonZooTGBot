# PythonZoo — сессионное задание по дисциплине «Язык программирования Python»

В рамках задания был сделан Telegram-бот с викториной, который помогает пользователю узнать своё «тотемное животное» из Московского зоопарка и познакомиться с программой опеки «Возьми животное под опеку».

Проект сделан в рамках учебного кейса для реального заказчика. Основной сценарий: пользователь проходит викторину, получает результат с животным, может узнать об опеке, поделиться результатом, связаться с сотрудником и оставить отзыв.

Бот доступен по ссылке https://t.me/KuryndinMoscowZooBot

---

## Возможности бота

- запуск викторины через меню;
- вопросы с вариантами ответов;
- перемешивание вопросов и вариантов;
- подсчёт баллов;
- определение итогового животного;
- показ результата с описанием и фотографией;
- сохранение результата в PostgreSQL;
- просмотр последнего результата через `/result`;
- информация о программе опеки Московского зоопарка;
- ссылка и контакты программы опеки;
- шаринг результата в Telegram, VK, WhatsApp и MAX;
- отправка сообщения сотруднику зоопарка;
- сбор обратной связи по викторине;
- генерация отдельной AI-картинки по результату;
- read-only админский режим;
- запуск на сервере AWS через Docker Compose.

---

## Основные сценарии

### Викторина

Пользователь запускает бота через `/start`, нажимает кнопку начала викторины и отвечает на вопросы. Вопросы и варианты ответов перемешиваются при каждом прохождении. За каждый ответ начисляются баллы нескольким животным, после чего бот выбирает животное с максимальным итоговым счётом.

Активная сессия викторины хранится в Redis. Это позволяет не держать состояние в памяти Python-процесса и корректно обрабатывать повторные нажатия, отмену и устаревшие кнопки.

### Результат

После последнего вопроса бот показывает персонализированный результат: название животного, описание характера и фотографию. Результат сохраняется в PostgreSQL, поэтому пользователь может вернуться к нему через `/result`.

### Программа опеки

После результата пользователь может открыть раздел с информацией о программе «Возьми животное под опеку». В этом разделе есть описание программы, ссылка на официальный сайт Московского зоопарка, Telegram-канал и контакты.

### Связь с сотрудником

Пользователь может отправить сообщение сотруднику зоопарка. Вместе с сообщением сотруднику передаётся результат викторины, чтобы контекст обращения был понятнее. Пользователь может выбрать способ отправки: Telegram или email.

### Обратная связь

Бот собирает оценки по нескольким критериям и необязательный комментарий. Отзыв отправляется сотруднику и сохраняется в PostgreSQL.

### AI-картинка

По результату викторины бот может сгенерировать отдельную AI-картинку. При генерации используются итоговое животное и теги, собранные из ответов пользователя.

## Команды пользователя

- `/start` — открыть стартовый экран;
- `/help` — справка;
- `/result` — показать последний результат;
- `/cancel` — отменить текущее действие.

## Команды администратора

- `/admin` — админский режим;
- `/admin_stats` — статистика проекта;
- `/admin_contacts` — последние обращения;
- `/admin_feedback` — последние отзывы.

Админские команды доступны только пользователю, чей Telegram ID указан в `ADMIN_CHAT_ID`.

## Безопасность

В проекте предусмотрены базовые меры безопасности и защиты пользовательских данных:

- секреты и пароли хранятся в `.env`;
- `.env` исключён из репозитория через `.gitignore` и из Docker build context через `.dockerignore`;
- настройки читаются через `pydantic-settings`;
- `BOT_LINK` валидируется как HTTPS-ссылка на Telegram;
- SQL-запросы выполняются через параметризованные запросы `asyncpg`;
- пользовательский текст ограничивается по длине перед отправкой сотруднику;
- email и Telegram username проходят валидацию;
- callback-значения для контактов и отзывов проверяются через whitelist;
- служебные сообщения сотруднику отправляются с `parse_mode=None`, без HTML/Markdown-разметки;
- контакт для ответа не сохраняется в PostgreSQL, а используется только в сообщении сотруднику;
- для контактов, отзывов и AI-генерации используется Redis cooldown;
- ответы викторины защищены Redis lock от двойных нажатий;
- повреждённая Redis-сессия викторины удаляется и не ломает handler;
- при сбое PostgreSQL во время сохранения результата пользователь всё равно получает результат;
- AI-генерация ограничена глобальным semaphore, чтобы не запускать слишком много генераций одновременно;
- в логи и Telegram-alert-ы не выводятся токены, пароли, prompt, `image_tags`, пользовательские сообщения и `callback.data`.

Проект использует следующую схему администрирования: `ADMIN_CHAT_ID` задаёт Telegram ID администратора, которому доступны admin-команды и технические уведомления.

## Логирование и мониторинг

В проекте используется стандартное логирование Python.

Логируются:

- запуск и остановка бота;
- подключение к PostgreSQL;
- подключение к Redis;
- регистрация router-ов;
- запуск polling;
- ошибки SMTP;
- ошибки Hugging Face;
- длительность AI-генерации;
- необработанные ошибки в handler-ах;
- критические ошибки запуска.

Для PostgreSQL настроены timeout-ы подключения и выполнения команд. Если база данных недоступна на старте, бот не зависает надолго, а завершает запуск с понятной ошибкой.

В проекте есть два уровня уведомлений администратора:

1. **Startup critical alert** — отправляется, если бот не смог запуститься из-за проблемы с PostgreSQL, Redis или другой обязательной частью запуска.
2. **Handler-level alert** — отправляется, если во время работы бота необработанное исключение возникло внутри handler-а.

Handler-level alert имеет cooldown, чтобы не заспамить администратора повторяющимися ошибками. Полный traceback остаётся только в логах сервера. В Telegram администратору отправляется короткое техническое сообщение без пользовательского текста, `callback.data`, токенов, паролей и других секретов.

    pip install -r requirements.txt

```
    migrations/001_init.sql
```

Запустить бота:

```
     python main.py
```


### Запуск через Docker Compose


Проект можно запустить через Docker Compose. В этом режиме поднимаются три сервиса:

- `bot` — Telegram-бот;
- `postgres` — PostgreSQL;
- `redis` — Redis.

Перед запуском нужно создать файл `.env` рядом с `docker-compose.yml`.

Для Docker Compose в `.env` важно указать:

```env
   DB_HOST=postgres
   REDIS_URL=redis://redis:6379/0
```

Запуск:

```
    docker compose up -d --build
```
Проверка контейнеров:

```
   docker compose ps
```

Просмотр логов бота:

```
   docker compose logs -f bot
```

Остановить только бота:

```
    docker compose stop bot
```

Запустить бота обратно:

```
    docker compose start bot
```

Остановить все контейнеры без удаления данных:

```
    docker compose down
```
Не использовать без необходимости:

```
docker compose down -v
```

Флаг -v удаляет Docker volumes, в которых хранятся данные PostgreSQL, Redis и сгенерированные изображения.

### Обновление на сервере

После изменения кода локально:

```bash
git add .
git commit -m "Update project"
git push
```
На сервере:
```
cd ~/MyPythonZooTGBot
git pull
docker compose up -d --build bot
docker compose logs -f bot
```
При таком обновлении пересобирается только контейнер бота. PostgreSQL и Redis не пересоздаются, данные сохраняются в Docker volumes.

### Что можно улучшить дальше (roadmap развития)

При дальнейшем развитии проекта можно усилить архитектуру и инфраструктуру в нескольких направлениях.

#### Dependency Injection

Сейчас сервисы, репозитории и настройки подключаются напрямую через импорты.

Если проект станет больше, зависимости можно вынести в DI: например, через middleware aiogram или отдельный контейнер. Это упростит тестирование, потому что базу, Redis, SMTP и генератор картинок можно будет подменять mock-объектами.

#### Хранилище для сгенерированных картинок

Сейчас AI-картинки сохраняются локально в `generated_images`. 

Если запускать несколько экземпляров бота, локальная папка станет проблемой: один контейнер не увидит картинки, которые создал другой. В таком случае изображения лучше вынести в S3-совместимое хранилище: AWS S3, Yandex Object Storage или MinIO.

#### Webhook вместо polling

Сейчас бот работает через polling. Этот вариант выбран для учебного проекта, потому что: не нужен публичный HTTPS endpoint, Nginx и настройка webhook.

Для production-версии можно перейти на webhook через `aiohttp` или FastAPI. Тогда Telegram будет сам отправлять обновления на endpoint бота, а перед приложением можно поставить Nginx для HTTPS и проксирования.

#### Миграции базы данных

Сейчас схема базы описана в `migrations/001_init.sql`.

Если таблиц и изменений станет больше, удобнее перейти на версионированные миграции, например через Alembic. Тогда каждое изменение схемы будет отдельным шагом, который проще применять на сервере и отслеживать в Git.

#### Провайдер генерации изображений

Сейчас генерация картинок завязана на Hugging Face Inference API. При развитии можно вынести генерацию за общий интерфейс.

Например, сделать `ImageGenerationProvider` и отдельную реализацию `HuggingFaceProvider`. Тогда позже можно будет подключить другой сервис генерации, не переписывая сценарий бота и логику prompt-а.
